# Frozen sizing scores on completed rollout probes

This is an offline comparison of previously fitted sizing laws at a supplied
frozen probe plan. It adds no fitting, new Teacher request, model selection,
market run, or change to historical prompts, actions, distributions or integer
settlement. It produces a new managed analysis artifact and preserves all input
bytes, modes and mtimes.

The first intended application is the 24-case, K=5 Teacher acquisition planned
from the original mean-Student rollout. Scoring that source does not validate
the trajectories generated by the newly added sampled-size markets. The API
does not hard-code that all future plans come from the mean policy: newer plans
may legitimately describe other verified trajectories. Stored legacy Student
predictions identify the frozen action model at the cases, not the policy that
generated the market. Consult the supplied plan's verified lineage to identify
that policy. Each score applies only to the supplied cases, not unprobed states.

## Frozen comparison

For each case, retain the same effective visible fields and account state that
were sent to the Teacher. Load the original selected Student and the completed
intensity-distribution study. Check every recorded case prediction against that
original Student, with absolute tolerance 1e-12 on each action probability and
legacy intensity. The distribution loader separately authenticates the
original model, encoder, normalized source identity and split binding.

Evaluate these four fixed candidates on exactly the same observed responses:

| Candidate | Predictive intensity law |
| --- | --- |
| `legacy_mean` | Point mass at the original Student's buy/sell intensity |
| `empirical` | Original training action-conditioned exact-support frequencies |
| `conditional_softmax` | Already fitted law from the frozen MLP representation |
| `selected` | The original distribution study's validation-selected law for each side |

`selected` may numerically duplicate another candidate. It is reported to
identify the actual proposed policy, not as an independent fit or replication.
This scorer has no candidate-selection, epoch, optimizer, endpoint or sampling
argument. It never reads original training/test labels, evaluates the old test,
updates a model, or uses new rollout scores to choose the winner. Such a future
development decision would require a separate explicit protocol and fresh
evaluation; it is not silently performed here.

## Metrics and exact denominators

Only valid observed **buy** responses contribute to buy sizing scores, and only
valid observed **sell** responses contribute to sell scores. No candidate's
predicted action is used to filter those labels. Holds remain holds and are
counted separately. Failed requests, missing responses and cases without a
particular action never become synthetic hold or zero-intensity observations.

For each case and side report N and:

- CRPS against the actual continuous intensity observation:
  `E|X-y| - 0.5 E|X-X'|`. This proper distribution score remains finite when an
  observation is not an atom of the training support. No snapping, artificial
  zero-density penalty or added support point is used.
- Mean absolute error of the predictive mean, `|E[X]-y|`. This measures the
  candidate's mean prediction, not the size of an independently sampled draw.
- Exact full-size event Brier, `(P(X=1) - 1[y=1])**2`. Near-one values are not
  relabeled as one. A point-mean candidate below one has zero full-size mass.

Predicted means/laws, exact endpoint probabilities, observed full-size counts,
and off-support counts are retained for audit. If N=0, each average score is
null; the prediction can still be displayed, but contributes no observation.

Two aggregates are reported for every candidate and side:

1. `row_weighted`: each valid response of that observed side has equal weight.
   Cases with more valid responses of the side receive more total weight.
2. `equal_case`: first average within each case and observed side, then give
   each contributing case equal weight. A case with zero valid responses of
   that side is excluded and explicitly counted; it is not filled with zero.

Both report contributing response count, case count, excluded case count and
the actual denominator. For `all_sides`, the within-case average includes all
valid non-hold responses before equal-case aggregation; it does not assign
equal weight to buy and sell irrespective of their observed frequencies.
These are descriptive finite-plan estimands, not population-weighted market
errors. Repeated K=5 responses may share state, request-time and endpoint
dependence. They are not five humans or five independent population samples.
No significance test, confidence interval, acceptance gate or human-validity
claim is inferred from these averages.

## Input validation and privacy

`nmsim.rollout_sizing_scores` is pure. Its public functions are:

```python
validate_scoring_inputs(plan, rows, original_study, distribution_study,
                       source_kind="openai")
score_rollout_sizing(plan, rows, original_study, distribution_study,
                    source_kind="openai")
descriptor()
```

`source_kind` is required and must be `openai` or `fake_test_teacher`; it is
never inferred from convenient response values. `validate_plan` and `summarize`
from `nmsim.rollout_probes` validate the canonical case/replicate request order,
prompt/observation identity, source/schema, sample roster, duplicates, decisions
and counts. This layer additionally requires the exact public acquisition-row
fields, positive integer attempts, finite valid intensities, hold=0,
buy/sell>0, the original empty/full-position feasibility constraint, valid-row
failure=None, failed-row decision=None, and a known acquisition failure code.
Valid responses require their public raw-response hash, expected reported model
and stop termination. Private rationale, raw response or other extra fields are
not accepted or propagated. The expected alias authenticates the historical
protocol's reported metadata; it is not proof of the endpoint's actual weights.

The pure API can diagnose explicitly incomplete synthetic/analysis inputs and
reports missing sample IDs. The **formal CLI** only accepts finished acquisition
runs, and the historical acquisition protocol requires no unresolved requests
for finished status. The CLI therefore rejects incomplete acquisitions, rather
than publishing interim responses as a completed endpoint evaluation.

`experiments.rollout_sizing_scores` is an official managed entrypoint. It:

- Rejects an output path inside any historical input before reserving a run,
  including a symlink or an invalid-argument failed-attempt path.
- Calls `verify_run` for source, original Student and distribution. A running
  or failed source is rejected before loading its response payload.
- Requires registered `probe_plan.json`, `probe_samples.jsonl`,
  `fidelity_summary.json` and `identities.json`, and acquisition run kind.
- Checks the acquisition's three config hashes and full effective hash,
  source kind, live/dry flags, plan identity, recomputed original summary,
  physical/logical accounting and zero unresolved requests.
- Hashes private source files only as part of integrity verification; it never
  parses them. Only public plan and samples enter scores. No Provider is
  constructed; no network connection, task acquisition or fitting is exposed.
- Preserves all three sources, checking their bytes/modes/mtimes again before
  completing the new output run. Outputs use exclusive creation.

`--help` and `--version` create no run. `--dry-run` validates complete inputs
and frozen model binding but does not create a new score table. It never fits
or calls a Provider. Acquisition summary recomputation and model predictions
used for binding validation are still numerical validation work.

## Artifacts and identities

The new public artifacts are `rollout_sizing_scores.json`, `summary.json`,
`input_validation.json`, `identities.json` and `source_receipts.json`, alongside
the ordinary managed lifecycle files. Dry-run omits `rollout_sizing_scores.json`.

The pure result schema is `rollout-sizing-scores/1.0`. It binds the plan hash,
frozen original action/encoder/data identities, distribution-study semantic
hash and original selected sizing candidates. Its canonical public-row hash
uses `rollout-sizing-public-probe-rows/1.0` and is distinct from the source JSONL
byte SHA, source manifest SHA, and result `score_semantic_hash`.

Under `rollout-sizing-scores-experiment/1.0`, `scientific_config_hash` covers the
scoring contract, exact public-sample byte identity, frozen model/plan binding
and scientific components. `model_request_config_hash` records zero new
Provider requests. `execution_config_hash` covers source manifests/snapshots,
dry mode, interpreter/platform, and entrypoint/I/O/loader bytes.
`full_effective_config_hash` binds all three. Each is explicitly named in
`identities.json`; none is a vague default Config hash or a child-resume token.

Example, only after the acquisition has finished:

```sh
python3 -m experiments.rollout_sizing_scores \
  --source-run /path/to/finished-probe-acquisition \
  --source-manifest-sha256 SOURCE_MANIFEST_SHA256 \
  --model-run /path/to/original-student-run \
  --model-manifest-sha256 MODEL_MANIFEST_SHA256 \
  --distribution-run /path/to/frozen-distribution-run \
  --distribution-manifest-sha256 DISTRIBUTION_MANIFEST_SHA256 \
  --out results_rollout_sizing_scores --run-id NEW_UNIQUE_RUN_ID
```

rules, missing/failure/hold denominators, empty null scores, exact endpoints,
off-support observations, frozen selection, model/source binding, no old-test
access, strict public projection, managed integrity, zero-network/fitting,
help/dry behavior and historical output protection. They require no ignored
